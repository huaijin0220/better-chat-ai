# better-chat-ai

## 项目简介

`better-chat-ai` 是一个用于规范 AI 任务处理行为的技能包。它帮助 AI 区分知识问答与操作型任务，并统一需求澄清、执行授权、风险确认、隐私保护、范围控制、结果验证和项目审查流程。

该技能强调：能直接回答的问题不增加流程负担；会改变文件、系统或外部状态的操作必须边界清晰；高风险操作必须额外确认；所有执行结果必须经过验证并如实汇报；AI 生成文件后必须进行项目审查，确保产物既执行成功又符合用户意图和质量标准。

## 功能

- 对纯知识问答直接回答。
- 在操作前识别目标、范围、限制条件、预期产物和验收标准。
- 在必要时采用一次一个关键问题的方式逐步澄清需求。
- 在需求明确后复述理解、给出方案并获取执行授权。
- 支持用户明确要求直接执行时跳过普通操作确认。
- 对删除、覆盖、系统配置、权限、软件安装和敏感数据处理进行额外风险确认。
- 将文件和数据访问限制在完成任务所需的最小范围内。
- 防止在回复、日志和交付物中泄露敏感信息。
- 要求执行后检查文件、内容、命令状态、测试结果或其他可验证证据。
- AI 完成文件生成或修改后，自动进行项目审查——双重验证：操作是否成功执行 + 产物是否符合用户意图和质量标准。
- 在范围或风险发生变化时暂停操作并重新获得授权。

## 安装方法

将整个 `better-chat-ai` 目录复制到支持自定义技能的技能目录中，并确保目录内的 `SKILL.md` 保持原有名称和 YAML frontmatter。

示例结构：

```text
<skills-directory>/
└── better-chat-ai/
    └── SKILL.md
```

重新加载技能列表或开启新对话后，确认系统能够识别名称为 `better-chat-ai` 的技能。不同客户端的技能目录和刷新方式可能不同，请以所使用产品的官方说明为准。

## 使用方式

当请求涉及以下场景时调用本技能：

- 用户提出纯知识咨询，需要直接、准确地回答。
- 用户要求创建、读取、修改、移动或删除文件。
- 用户要求运行命令、调用外部服务或改变系统状态。
- 任务存在需求歧义，需要逐步澄清关键条件。
- 用户要求直接执行，但仍需判断操作是否属于高风险。
- 任务可能接触敏感数据，或执行后需要提供可验证结果。
- AI 完成文件生成或修改后，需要审查产物是否符合用户意图和质量标准。

使用示例见 [examples/usage.md](examples/usage.md)。

## 行为边界

- 本技能不替代平台安全策略、系统权限或更高优先级指令。
- 用户对普通操作的直接执行授权不自动覆盖高风险操作。
- 一次授权仅适用于已说明的对象、范围和操作，不得自行扩大。
- 无法验证的执行结果必须明确标注为未验证，不能声称成功。
- 项目审查必须同时通过执行验证和意图质量审查方可声称完成，仅通过执行验证但未通过意图审查不得表述为全部完成。
- 遇到权限不足、依赖缺失、目标冲突或范围变化时，应停止相关步骤并说明原因。
- 不应在仓库、回复或日志中保存真实凭据、私钥或个人敏感数据。

3. 更新行为规则时同步更新 README、示例和变更记录。
4. 提交前检查 YAML frontmatter、Markdown 格式和内部链接。
5. 清楚说明修改动机、行为变化、兼容性影响和验证方式。
